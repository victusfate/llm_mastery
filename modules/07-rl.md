# Module 7: reinforcement learning foundations

Full route: Weeks 22–24, 156 hours. Bootcamp: Weeks 14–15, 104 hours. Dependencies: gradients, probability, and training-loop fluency.

## Outcome

You understand policy-gradient estimation well enough to debug RL on tiny problems before applying it to language models.

## Concepts to explain

For a policy pi_theta, maximize expected return `J(theta) = E_tau[R(tau)]`. The score-function identity yields an estimator using `grad log pi_theta(a|s)` multiplied by a return or advantage estimate. An action-independent baseline can reduce variance without changing the expected policy gradient under the appropriate sampling assumptions. Read the [policy-optimization derivation](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html).

Define MDP, reward, discounted return, value, Q, advantage, credit assignment, exploration, entropy, on/off-policy data, bootstrapping, and importance sampling. For GAE, connect TD residuals and the gamma/lambda bias–variance choice. Distinguish true termination from a time-limit truncation.

PPO uses a ratio to the rollout policy and a clipped surrogate. Read the [PPO paper](https://arxiv.org/abs/1707.06347); clipping is an optimization device, not a hard guarantee of a small KL divergence.

## Labs

1. Implement a two-action bandit with known rewards. Compute expected reward and its gradient exactly; compare the Monte Carlo estimator across sample sizes and random seeds. Add a baseline and measure estimator variance.
2. Implement a small finite-horizon chain environment with a known or enumerable optimal policy. Train REINFORCE, then actor-critic. Plot returns, entropy, value loss, and policy probabilities; compare to random and optimal baselines.
3. Add GAE and clipped PPO, retaining the rollout policy’s log probabilities. Test ratios equal one before an update, loss sign for positive/negative advantages, terminal versus truncated bootstrapping, padding, and minibatch aggregation.
4. Change reward scale and rollout length separately. Explain instability with evidence rather than repeatedly tuning until one seed succeeds.

## Gate

Derive the bandit gradient from memory, explain why an implementation’s sign or baseline is wrong, and repair a terminal-state bug. Show all seeds and at least one failed run with a diagnosis.

All mandatory labs can run on CPU. Stretch: off-policy estimators or an additional classic control environment. Do not spend GPU time debugging a policy-gradient sign error.
