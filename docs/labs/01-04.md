## Walkthrough: build a debugging decision tree

Reuse the verified model and data generator from Lab 01-02. Save a clean starting configuration. Your job is to distinguish implementation bugs, optimization difficulty, and generalization failure using controlled evidence.

Run the tiny-batch overfit control. Then freeze a separate run’s random training labels and repeat training. Evaluate those arbitrary labels only with a clearly defined held-out-label policy; do not accidentally regenerate labels on every step. Explain why fitting fixed random labels does not establish useful prediction.

Introduce one bug at a time in separate local variants. First omit the gradient reset. Compare gradient norms after identical repeated batches and inspect whether each step accidentally includes old contributions. Next detach the logits before constructing the loss; investigate the missing gradient path rather than trying a new optimizer. Finally, deliberately misalign labels and confirm that inspecting the data catches the problem.

For training/evaluation mode, add a dropout layer to a small variant. Compare repeated predictions with training mode enabled versus evaluation mode. Explain why disabling graph recording alone does not disable dropout. Keep the original no-dropout model as a reference.

For each bug, write the symptom, two plausible explanations, the smallest discriminating test, the fix, and a regression check. A diagnosis should predict an observation before you run it. Save the failure traces as well as the successful result.

**Independent check:** ask the tutor to introduce one undisclosed fault into a copy of the small loop. Diagnose it without requesting the corrected implementation. You may use normal logging and debugging tools; explain which observation ruled out each alternative.
