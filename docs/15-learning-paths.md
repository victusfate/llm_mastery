# Choose your learning route

This course is for developers who want to understand and implement deep-learning training. You do not need an aerospace background, a startup résumé, a particular programming language, or an expensive GPU. You should be able to write and debug a small program; use the bridge to build the Python and math needed for the labs.

## Start with meaning, then evidence

1. Read a plain definition and inspect its visual example.
2. Predict an outcome before moving a control or running code.
3. Follow the worked walkthrough, then change one assumption.
4. Explore a related concept, paper, lecture, or conversation with your preferred tutor.
5. Close the explanation and attempt a fresh retrieval check. Record confidence before feedback.
6. Build a small implementation and defend the result with tests and measurements.
7. Return after a delay and apply the idea in a different setting.

Move forward when you can explain and use the idea. When a check fails, use the failure to choose a smaller explanation or contrasting example. Time spent and familiarity are not mastery. Correct numerical answers demonstrate a narrow check; practical gates require independent evidence and review.

## Routes

| Starting point | First step | Pacing |
| --- | --- | --- |
| Developer new to ML | [Prerequisite bridge](../modules/00-bridge.md), then foundations | Work in 30–60 minute sessions; use the fuller curriculum as a sequence, not a deadline |
| Developer with basic ML | Foundations walkthrough and [placement](../assessments/00-placement.md) | Skip only skills demonstrated independently; spend more time on unfamiliar training topics |
| Experienced ML engineer | Diagnostic and weak-area review | Optional [24-week intensive plan](00-personalized-bootcamp.md); accelerate only with evidence |

The curriculum describes scope, not a universal completion time. At 5, 10, or 20 hours per week, plan a longer calendar than the intensive route. Reforecast after the first few completed labs; do not multiply reading speed into a mastery estimate.

## Hardware and cost

| Available resources | Meaningful work |
| --- | --- |
| Browser only | Definitions, visual experiments, theory checks, papers, tutor handoffs |
| Laptop CPU | NumPy, autograd, tiny models, data pipeline tests and evaluation fixtures |
| One GPU or Apple Silicon | Larger local experiments within measured memory limits |
| Multiple GPUs or optional cloud | Communication, sharding and scaling extensions after local correctness |

The [home hardware guide](09-home-lab.md) is an example configuration, not an entry requirement. Cloud spending is optional and should follow a concrete experiment plan. A small run can demonstrate an algorithm; it cannot establish experience operating frontier-scale training.

## Contribution path

Begin with reproducible documentation fixes, CPU-sized regression tests, data checks or evaluation fixtures. Use the [open-source lane](08-open-source.md) to identify candidates, then verify current maintainer priorities before investing effort. The course does not require public contribution acceptance to continue learning.

## Confidence and progress

The study coach uses recent correct/incorrect and assisted/unaided attempts plus due review dates. It is a transparent heuristic, not an inferred psychological profile or a validated mastery classifier. Confidence is recorded with each attempt and exported with progress. A high-confidence error suggests checking the underlying assumption; an uncertain correct answer suggests practicing explanation and delayed recall.
